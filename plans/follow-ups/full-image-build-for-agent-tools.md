- **Kind:** Post-merge task.

Updated on 2026-11-10 by branch `calummoore/workspace-name-underscores`, which adds guidance against underscores to the name of a create call. - **Reason:** The checks need the deployed Worker and current sandbox release, with a new session that takes current instructions.

- **Terms:**
  - **Workspace tools:** the `conductive` CLI and MCP server in each cloud computer, in `crates/cnd-tools/`. They have 24 calls. Agents use them to create, list, get, rename, move, and archive workspaces, to create, list, read, get, rename, close, and stop sessions, and to send and get messages. They also create, list, and delete sections, open, list, and close port previews, list repositories and models, and ask to run a command on a Mac.
  - **Org image:** the saved image that each new cloud computer of an org starts from. A full build installs the workspace tools into it. Existing computers also receive the tools through automatic software updates at a later start.
  - **Sender line:** the first line of each message that reaches the agent, such as `Sender: Alice Example (@alice) [member ID: "member-alice-id"]`. It names the member who sent that message. The runner of the org image writes it, and the chat never shows it.
  - **Stop line:** the line in the chat after a stopped turn. For a stop through the workspace tools, it shows **Stopped from** and a chip of the sending session: a small box with the workspace state, number, a session icon, and the session title.
- **Background:**
  - The branch `calummoore/mcps-for-agents` adds the tool calls `list_repositories`, `list_sections`, and `list_models`, and an optional `name` for `create_workspace`.
  - The branch `calummoore/workspace-name-underscores` adds two sentences to the `name` description of `create_workspace` in `tools/mcp-tools.ts`, and to the `--name` help of `conductive --help` in `tools/cli.ts`: "Use plain words separated by spaces. Avoid underscores unless the user tells you to add them." These texts now live in `crates/cnd-tools/src/mcp-tools.json` and `crates/cnd-tools/src/help.txt`. The help gives the two sentences once, for `--name`, `--title`, and `--first-session-title`.
  - The branch `calummoore/conductive-mcp-chat-access` adds the session calls `list_sessions`, `read_session`, `create_session`, and `send_message`. The CLI commands are `conductive sessions list`, `read`, `create`, and `send`. Session writes need an active agent turn. Session reads need only the workspace token.
  - Tool messages end with `Sent by:` and the sending session link. New runner instructions explain that line and tell agents not to reply only to confirm it.
  - The user chose on 10 November 2026 that the Worker keeps the underscores of a name that an agent gives. So this text is the only guidance that keeps underscores out of such a name.
  - The branch `calummoore/untitled-v3` adds 14 calls. With the 10 earlier calls, including `run_mac_command`, the tools have 24 calls. The new calls and their CLI commands are:
    - `get_workspace`: `conductive workspaces get [--workspace ID]`
    - `rename_workspace`: `conductive workspaces rename --name TEXT [--workspace ID]`
    - `move_workspace`: `conductive workspaces move --section ID [--workspace ID]`
    - `archive_workspace`: `conductive workspaces archive [--workspace ID]`
    - `get_session`: `conductive sessions get --session ID [--workspace ID]`
    - `rename_session`: `conductive sessions rename --session ID --title TEXT [--workspace ID]`
    - `close_session`: `conductive sessions close --session ID [--workspace ID] [--stop-running-turn]`
    - `stop_session`: `conductive sessions stop --session ID [--workspace ID]`
    - `get_message`: `conductive messages get --session ID --message-id ID [--workspace ID]`
    - `create_section`: `conductive sections create --name TEXT`
    - `delete_section`: `conductive sections delete --section ID`
    - `list_previews`: `conductive previews list [--workspace ID]`
    - `open_preview`: `conductive previews open --port NUMBER [--workspace ID]`
    - `close_preview`: `conductive previews close --preview ID [--workspace ID]`
  - The same branch adds options to earlier calls. `conductive workspaces list` takes `--owner MEMBER_ID`, `--state STATE`, `--repository ID`, `--query TEXT`, `--updated-since MILLISECONDS`, and `--archived true|false`. The workspace and session lists take `--limit NUMBER`, from 1 to 100, and `--offset NUMBER`. A reply to a list with a limit gives `hasMore`. A list without options returns every entry, as before. `conductive workspaces create` takes `--first-session-title TEXT` and `--request-id ID`. A repeat with the same request ID returns the first workspace and makes no second workspace. An omitted request ID makes a new ID for that call only. The MCP tools take the same values as fields, such as `ownerId`, `updatedSince`, `firstSessionTitle`, `requestId`, and `stopRunningTurn`.
  - `conductive workspaces create`, `conductive sessions create`, and `conductive sessions send` take `--message-file PATH` in place of `--message TEXT`. `--message-file -` reads raw stdin. The text keeps all spaces, line endings, and final newlines. A call with both options fails with "Use --message or --message-file for one message." and sends no request. The MCP server takes the text only.
  - Each read needs only the workspace token. Each write needs an active calling turn, and it acts for the member whose message started that turn, with that member's rights in the app. Only the workspace owner or an org admin can archive a workspace. Another sender gets HTTP 403 `archive_forbidden`. A member can restore an archived workspace for 14 days. Archiving the calling workspace ends the calling turn. Stopping or closing the calling session can end it too.
  - A close of a session with a running turn gets HTTP 409 `stop_confirmation_required`, unless it gives `--stop-running-turn`. A stop of a session without a running turn succeeds with `state: "idle"`. A delete of the default section changes nothing and succeeds with `deleted: false`. A close of a preview that is already closed succeeds with `closed: false`. Preview links need a member's sign-in.
  - The user chose on 11 November 2026 that the workspace list has no mine filter, and that its owner filter takes only a member ID, with no login lookup. On the same day, the user chose that each sender line gives the member ID of that message's own sender, and that each row of the workspace list gives its owner's member ID, GitHub login, and display name. The instructions of a new session tell the agent to pass that message's member ID as `ownerId` for the sender's workspaces, and to take another owner's ID from the owner fields. A later message of another member does not change the turn sender, the tool access, or the commit author.
  - The user chose on 11 November 2026 that the chat names the sending session of a stop through the tools with a session chip. This holds also for a close that stops a turn. The stop line shows **Stopped from** and that chip. The copy of a transcript gives the same words with the session link.
  - The runner puts the tool guidance in the instructions of each new session. An existing session keeps its saved instructions, also after a restart. So only a new session shows the new instructions.
  - The Worker serves the new routes at once after the deploy.
  - The Rust release includes the CLI and MCP server. Existing computers download it in the background and apply it at a later runner start. A computer without the program receives a background bootstrap at its next start.
  - A build also installs the newest release. No full rebuild is required to update existing workspaces. Confirm the installed release before checking the tools. New sessions take current instructions, while existing sessions keep their saved text.
  - Older tools keep working. They do not show the new calls, and they drop a `name`.
  - Tools from a full build between the deploys of the two branches send a `name`. They give the agent the old text, with no guidance against underscores.
  - The CLI and the MCP server come from the same tool sources and the same install step. So a check of the CLI help also shows that the MCP description is new.
- **Task:**
  1. After the deploy, let a test workspace download the current release. At a later normal start, confirm that the release applied. Alternatively, build a test org image and create a workspace from it.
  2. In that workspace, run `conductive repositories list`, `conductive sections list`, and `conductive models list` in its terminal. Also run `conductive --help`, and check that the `--name` help gives the two sentences above. Check that the help also lists the 14 new commands and the new options.
  3. Run `conductive sessions list` and `conductive sessions read` for a session. During an active agent turn, use `conductive sessions create` in another workspace, then `conductive sessions send` and `conductive sessions read` for that session. Check that MCP exposes and runs the same four calls. Press the link of the `Sent by:` line and check that the sending session opens.
  4. Check that the MCP tool list gives all 24 calls: the 10 earlier calls, including `run_mac_command`, and the 14 new calls. This task runs no Mac command.
  5. In a new session of the new workspace, let an agent use each new call once: get, rename, move, and archive a workspace, get, rename, stop, and close a session, get a message, create and delete a section, and open, list, and close a preview. Use a spare workspace, sessions, and a section for the calls that change or end work. Let the agent stop a spare session while its turn runs. Let it close another spare session while its turn runs, with `--stop-running-turn`.
  6. Check that the app shows the stop line in both stopped sessions: **Stopped from** and the chip of the sending session. Reopen the closed session from **Session history** to see its line.
  7. Run `conductive workspaces list` with each filter, and both lists with `--limit` and `--offset`. Check `hasMore`. Create a workspace with `--first-session-title`, and check that its first session shows that title. Repeat the create with the same `--request-id`, and check that the repeat returns the same workspace.
  8. Run each of `conductive workspaces create`, `conductive sessions create`, and `conductive sessions send` once with `--message-file PATH` and once with `--message-file -` on stdin. Use text with leading spaces, several lines, and a final newline. Check that each message arrives. For each session create and send, use `conductive messages get` with the message ID of its reply. Check that the stored text keeps the spaces, the lines, and the final newline before its `Sent by:` line.
  9. Check that a delete of the default section gives `deleted: false`, a second close of a preview gives `closed: false`, and a stop of an idle session gives `state: "idle"`. Each is a success: exit status 0 in the CLI, and `isError: false` in MCP. Open the link of the new preview in a browser, and check that it needs a member's sign-in.
  10. Ask the agent of the new session for the sender and the member ID of a message. Let a second org member send a message during a turn of that session. Check that the agent gives the second member's own ID, and that `conductive workspaces list --owner` with that ID lists the workspaces of the second member. Check that a write in that turn still acts for the first sender, for example that a new session names the first sender as its starter.
